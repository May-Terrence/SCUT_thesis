\chapter{涵道风扇式无人机的轨迹规划设计}

为了提升DFUAV的自主性，满足复杂环境下的飞行需求，本章对DFUAV的轨迹规划问题展开研究。根据第一章的介绍，轨迹规划过程一般分为路径规划和轨迹优化两个阶段。在路径规划阶段，为了在复杂环境中快速找到无碰撞的初始路线，本文选用基于采样的RRT路径搜索算法。但常规的RRT算法存在采样效率低下和搜索路径非最优的问题，因此本章针对上述问题提出C-RRT*算法以加快路径搜索速度，同时在搜索过程中保证路径的最优性。在轨迹优化阶段，针对不平滑且不满足DFUAV动力学约束的初始路径，采用B样条曲线对其进行平滑处理，以保证DFUAV的飞行安全性和稳定性。

本章安排如下：首先介绍RRT路径搜索算法及其改进算法RRT-Connect算法和RRT*算法的基本原理，然后结合RRT-Connect算法和RRT*算法的优势提出C-RRT*算法。接下来介绍B样条曲线的基本原理，并使用B样条曲线法对C-RRT*算法寻找的初始路径进行优化。最后使用第四章设计的DFUAV的基于INDI的位置控制器对轨迹规划结果进行跟踪实验。

\section{RRT算法及其改进算法理论介绍}

\subsection{RRT算法}

快速扩展随机树(Rapidly-exploring Random Tree, rrt)算法是一种随机采样的路径搜索算法，其基本思想是从树的根节点(起点)出发，通过随机采样的方式不断扩展树的子节点，一旦扩展到目标点附近，那么就可以通过回溯树的路径来生成从起点到目标点的路径。RRT算法的伪代码如算法\ref{RRT算法}所示：
\begin{algorithm}
\caption{RRT算法}
\label{RRT算法}
\begin{algorithmic}[1]
    \setlength{\baselineskip}{16pt}
\State $\boldsymbol{T}\leftarrow\boldsymbol{x}_{start};\boldsymbol{E}\leftarrow\emptyset;$
\While{true}
    \State $\boldsymbol{x}_{rand}=\text{RandomSample}();$
    \State $\boldsymbol{x}_{near}=\text{GetNearest}(\boldsymbol{x}_{rand},\boldsymbol{T});$
    \State $\boldsymbol{x}_{new}=\text{GetNewNode}(\boldsymbol{x}_{rand},\boldsymbol{x}_{near},t);$
    \If{$\text{CollisionCheck}(\boldsymbol{x}_{new},\boldsymbol{x}_{near}) == \text{true}$}
        \State $\boldsymbol{T}\leftarrow \boldsymbol{T}\cup\{\boldsymbol{x}_{new}\};$
        $\boldsymbol{E}\leftarrow \boldsymbol{E}\cup\{\boldsymbol{x}_{near},\boldsymbol{x}_{new}\};$
        \If{$\text{dist}(\boldsymbol{x}_{new},\boldsymbol{x}_{goal}) < d_{th}$}
        \State break
        \EndIf
    \EndIf
\EndWhile
\end{algorithmic}
\end{algorithm}

其中，$\boldsymbol{T}$表示RRT随机树节点的集合，$\boldsymbol{E}$表示RRT随机树的边集合，表示节点之间的连接关系。算法开始先将起点$\boldsymbol{x}_{start}$作为树的初始节点加入集合$\boldsymbol{T}$，并将边集合置为空集。然后循环在可行域内随机采样，对每一个采样点$\boldsymbol{x}_{rand}$，都可以找到树节点集合$\boldsymbol{T}$中距离$\boldsymbol{x}_{rand}$最近的节点$\boldsymbol{x}_{near}$。然后在节点向量$\boldsymbol{x}_{near}-\boldsymbol{x}_{rand}$方向上以固定的步长$t$生成一个新节点$\boldsymbol{x}_{new}$，并检查$\boldsymbol{x}_{new}$和$\boldsymbol{x}_{near}$之间的连线与障碍物是否存在碰撞，如果不存在碰撞，则将$\boldsymbol{x}_{new}$加入到集合$\boldsymbol{T}$中并且将边$\{\boldsymbol{x}_{near},\boldsymbol{x}_{new}\}$添加到集合$\boldsymbol{E}$中。接下来判断新节点$\boldsymbol{x}_{new}$是否与目标点$\boldsymbol{x}_{goal}$的距离小于设定的距离阈值$d_{th}$，如果是则跳出循环返回路径搜索结果，否则继续下一次迭代过程，直至到达目标点附近为止。

根据RRT算法的原理可知，如果存在从起点到目标点的无碰撞路径，那么在有限的时间内，RRT算法一定会找到一条可行的路径。图\ref{RRT算法仿真结果}展示了RRT算法仿真实验结果。

RRT算法存在采样效率低和搜索路径非最优的问题：一方面，RRT算法每次都是在可行域内均匀随机采样，缺乏目标导向，这就会导致搜索可行路径的过程中可能会搜索到大量的无效节点，从而浪费大量时间和计算资源；另一方面，RRT算法在搜索路径的时候没有优化过程，导致最终路径可能经过许多不必要的节点，从而导致路径长度较长，非最优路径。为了解决上述问题，研究者们提出了RRT-Connect算法和RRT*算法。

\subsection{RRT-Connect算法和RRT*算法}

\subsubsection{RRT-Connect算法}

为了解决传统的RRT算法搜索路径的单源性和搜索效率低下的局限性，有研究学者提出了RRT-Connect算法，该算法相比RRT算法添加了双向协同搜索架构和贪婪扩展策略，其基本思想是构建起点和目标点两棵随机树，通过交替执行拓展操作逼近彼此，并且通过贪婪策略以加快路径搜索速度。
RRT-Connect算法的伪代码如算法\ref{RRT-Connect算法}所示：
\begin{algorithm}
    \caption{RRT-Connect算法}
    \label{RRT-Connect算法}
    \begin{algorithmic}[1]
        \setlength{\baselineskip}{16pt}
        % \setcounter{ALG@line}{4}
        \State $\boldsymbol{T}_1\leftarrow\boldsymbol{x}_{start};\boldsymbol{E}_1\leftarrow\emptyset;$
        \State $\boldsymbol{T}_2\leftarrow\boldsymbol{x}_{end};\boldsymbol{E}_2\leftarrow\emptyset;$
        \While{true}
            \State $\boldsymbol{x}_{rand}=\text{RandomSample}();$
            \State $\boldsymbol{x}_{near1}=\text{GetNearest}(\boldsymbol{x}_{rand},\boldsymbol{T}_1);$
            \State $\boldsymbol{x}_{new1}=\text{GetNewNode}(\boldsymbol{x}_{rand},\boldsymbol{x}_{near1},t);$
            \If{$\text{CollisionCheck}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near1}) == \text{true}$}
                \State $\boldsymbol{T}_1\leftarrow \boldsymbol{T}_1\cup\{\boldsymbol{x}_{new1}\};$
                $\boldsymbol{E}_1\leftarrow \boldsymbol{E}_1\cup\{\boldsymbol{x}_{near1},\boldsymbol{x}_{new1}\};$
                \State $\boldsymbol{x}_{near2}=\text{GetNearest}(\boldsymbol{x}_{new1},\boldsymbol{T}_2);$
                \If{$\text{CollisionCheck}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2}) == \text{true} \text{ \&\& } \text{dist}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2}) < d_{th}$}
                    \State break
                \EndIf
                \State $\boldsymbol{x}_{new2}=\text{GetNewNode}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2},t);$
                \While{$\text{CollisionCheck}(\boldsymbol{x}_{new2},\boldsymbol{x}_{near2}) == \text{true}$}
                \State $\boldsymbol{T}_2\leftarrow \boldsymbol{T}_2\cup\{\boldsymbol{x}_{new2}\};$
                $\boldsymbol{E}_2\leftarrow \boldsymbol{E}_2\cup\{\boldsymbol{x}_{near2},\boldsymbol{x}_{new2}\};$
                \State $\boldsymbol{x}_{near2}=\boldsymbol{x}_{new2};$
                \State $\boldsymbol{x}_{new2}=\text{GetNewNode}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2},t);$
                \EndWhile
                \State swap$(\boldsymbol{T}_1,\boldsymbol{T}_2);$swap$(\boldsymbol{E}_1,\boldsymbol{E}_2);$
            \EndIf
        \EndWhile
\end{algorithmic}
\end{algorithm}

根据RRT-Connect算法流程可知，相比于RRT算法，RRT-Connect算法在初始化阶段建立了两棵随机树，并将起点和目标点分别作为两棵随机树的初始节点。然后执行与RRT算法相同的步骤来循环地随机寻找新节点$\boldsymbol{x}_{new1}$，不同的是在随机找到新节点后，会判断新节点与另一棵树的最近节点$\boldsymbol{x}_{near2}$之间是否不存在碰撞以及距离是否小于阈值$d_{th}$，如果两个条件都满足的话，则跳出循环并返回路径搜索结果。如果任一条件不满足，则在$\boldsymbol{x}_{near2}-\boldsymbol{x}_{new1}$方向上以固定的步长$t$生成一个新节点$\boldsymbol{x}_{new2}$，并检查节点$\boldsymbol{x}_{new2}$与节点$\boldsymbol{x}_{near2}$之间是否存在碰撞，如果不存在碰撞，则将$\boldsymbol{x}_{new2}$加入到集合$\boldsymbol{T}_2$中并且将边$\{\boldsymbol{x}_{near2},\boldsymbol{x}_{new2}\}$添加到集合$\boldsymbol{E}_2$中。然后执行贪婪策略，随机树$\boldsymbol{T}_2$以$\boldsymbol{x}_{new2}$为新的起点(设置为$\boldsymbol{x}_{near2}$)继续向$\boldsymbol{x}_{new1}$方向生成新节点，直到检测到新节点与$\boldsymbol{x}_{near2}$之间存在碰撞为止。如果存在碰撞，则交换两棵随机树的节点集合和边集合，继续下一次随机采样过程，直至找到一条可行路径。

图\ref{RRT-Connect算法仿真结果}展示了使用RRT-Connect算法进行路径规划仿真的结果。由于RRT-Connect算法中的两棵树是双向生长的，并且通过贪婪策略优先在两棵树之间节点的可扩展区域进行生长，使得两棵树可以快速相交。所以RRT-Connect相比于RRT算法大量减少了无效节点的生成，加快了路径搜索的速度。但是由于RRT-Connect算法的单次查询性质，其仍然存在路径非最优的问题。

\subsubsection{RRT*算法}

为了解决RRT算法中路径非最优的问题，有研究学者提出了RRT*算法。RRT*算法属于渐进优化的算法，其基本思想是在随机树中添加新节点时，通过对新节点邻域半径内的节点进行选择性地重连操作，以保证选取的是当前范围内的最优父节点，并借助新节点使用重布线优化机制动态优化树结构，进一步提高路径的最优性。RRT*算法的伪代码如算法\ref{RRT*算法}所示。
\begin{algorithm}
    \caption{RRT*算法}
    \label{RRT*算法}
    \begin{algorithmic}[1]
        \setlength{\baselineskip}{16pt}
        \State $\boldsymbol{T}\leftarrow\boldsymbol{x}_{start};\boldsymbol{E}\leftarrow\emptyset;$
        \While{true}
            \State $\boldsymbol{x}_{rand}=\text{RandomSample}();$
            \State $\boldsymbol{x}_{near}=\text{GetNearest}(\boldsymbol{x}_{rand},\boldsymbol{T});$
            \State $\boldsymbol{x}_{new}=\text{GetNewNode}(\boldsymbol{x}_{rand},\boldsymbol{x}_{near},t);$
            \If{$\text{CollisionCheck}(\boldsymbol{x}_{new},\boldsymbol{x}_{near}) == \text{true}$}
                \State $\boldsymbol{T}\leftarrow \boldsymbol{T}\cup\{\boldsymbol{x}_{new}\};$
                $\boldsymbol{E}\leftarrow \boldsymbol{E}\cup\{\boldsymbol{x}_{near},\boldsymbol{x}_{new}\};$
                \State $\boldsymbol{C}=\text{GetNodeInCircle}(\boldsymbol{x}_{new},\boldsymbol{T},r);$
                \State $\boldsymbol{x}_{near\_new}=\text{GetNearest}(\boldsymbol{x}_{new},\boldsymbol{C});$
                \State $\boldsymbol{E}\leftarrow \boldsymbol{E}\setminus\{\boldsymbol{x}_{near},\boldsymbol{x}_{new}\};$
                $\boldsymbol{E}\leftarrow \boldsymbol{E}\cup\{\boldsymbol{x}_{near\_new},\boldsymbol{x}_{new}\};$
                \If{$\text{CollisionCheck}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2}) == \text{true} \text{ \&\& } \text{dist}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2}) < d_{th}$}
                    \State break
                \EndIf
                \State $\boldsymbol{x}_{new2}=\text{GetNewNode}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2},t);$
                \While{$\text{CollisionCheck}(\boldsymbol{x}_{new2},\boldsymbol{x}_{near2}) == \text{true}$}
                \State $\boldsymbol{T}_2\leftarrow \boldsymbol{T}_2\cup\{\boldsymbol{x}_{new2}\};$
                $\boldsymbol{E}_2\leftarrow \boldsymbol{E}_2\cup\{\boldsymbol{x}_{near2},\boldsymbol{x}_{new2}\};$
                \State $\boldsymbol{x}_{near2}=\boldsymbol{x}_{new2};$
                \State $\boldsymbol{x}_{new2}=\text{GetNewNode}(\boldsymbol{x}_{new1},\boldsymbol{x}_{near2},t);$
                \EndWhile
                \State swap$(\boldsymbol{T}_1,\boldsymbol{T}_2);$swap$(\boldsymbol{E}_1,\boldsymbol{E}_2);$
            \EndIf
        \EndWhile
\end{algorithmic}
\end{algorithm}
